# Strategy Alignment Checklist

## Overview

This checklist ensures content follows product strategy recommendations. Use this for every content piece to validate strategy compliance.

---

## Checklist Items

### Platform Compliance
- [ ] Content is for a recommended platform (not "avoid")
- [ ] Content format matches platform recommendations
- [ ] Content style matches platform best practices
- [ ] Warning displayed if using "avoid" platform (if implemented)

**Status**: [Compliant / Non-Compliant / Partial]

---

### Tone & Voice Compliance
- [ ] Tone matches strategy recommendations
- [ ] Style matches strategy examples
- [ ] Avoided tone elements are not present
- [ ] Language is appropriate for strategy

**Status**: [Compliant / Non-Compliant / Partial]

---

### Content Type Compliance
- [ ] Content type is recommended
- [ ] Content type matches strategy
- [ ] Avoided content types are not used

**Status**: [Compliant / Non-Compliant / Partial]

---

### Proof Type Compliance
- [ ] Uses recommended proof types
- [ ] Proof types are appropriate
- [ ] Proof types are credible

**Status**: [Compliant / Non-Compliant / Partial]

---

### Anti-Pattern Avoidance
- [ ] Anti-patterns from strategy are avoided
- [ ] Content doesn't violate "what NOT to do" guidance
- [ ] Content follows strategy's avoid list

**Status**: [Compliant / Non-Compliant / Partial]

---

### Posting Cadence Compliance
- [ ] Content frequency matches cadence recommendations (if applicable)
- [ ] Timing is appropriate (if applicable)

**Status**: [Compliant / Non-Compliant / Partial]

---

## Overall Compliance Assessment

### Compliance Levels
- **Full Compliance**: All checklist items pass
- **Partial Compliance**: Most items pass, minor deviations
- **Non-Compliance**: Significant deviations from strategy

### Compliance Rate
- Calculate: (Compliant Items / Total Items) * 100%
- **Target**: ≥ 90% compliance rate

---

## Strategy-Specific Checks

### For SaaS Products
- [ ] Technical language appropriate
- [ ] Developer-focused (if audience is developers)
- [ ] Avoids marketing hype
- [ ] Uses code/examples appropriately

### For Course Products
- [ ] Educational tone
- [ ] Helpful and informative
- [ ] Avoids salesy language
- [ ] Focuses on learning outcomes

### For Coaching Products
- [ ] Personal and empathetic
- [ ] Authentic voice
- [ ] Avoids generic advice
- [ ] Focuses on transformation

---

## Usage Notes

- Use this checklist for every content piece
- Check compliance before approving content
- Document non-compliance issues
- Use checklist to guide content improvements
- Track compliance rate over time

---

## Example Assessment

### Example 1: Fully Compliant
- Platform: ✅ Compliant (LinkedIn recommended)
- Tone: ✅ Compliant (matches strategy)
- Content Type: ✅ Compliant (post recommended)
- Proof Types: ✅ Compliant (uses recommended types)
- Anti-Patterns: ✅ Compliant (all avoided)
- **Overall**: Full Compliance (100%)

### Example 2: Partially Compliant
- Platform: ✅ Compliant
- Tone: ⚠️ Partial (mostly matches, minor deviation)
- Content Type: ✅ Compliant
- Proof Types: ✅ Compliant
- Anti-Patterns: ⚠️ Partial (one anti-pattern present)
- **Overall**: Partial Compliance (80%)

### Example 3: Non-Compliant
- Platform: ❌ Non-Compliant (using "avoid" platform)
- Tone: ❌ Non-Compliant (doesn't match strategy)
- Content Type: ✅ Compliant
- Proof Types: ⚠️ Partial
- Anti-Patterns: ❌ Non-Compliant (multiple anti-patterns)
- **Overall**: Non-Compliance (40%)
